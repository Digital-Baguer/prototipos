Cómo sabe el bot de qué anuncio vienes — el webhook por dentro

La atribución de F1 no es inteligencia artificial: es leer un campo de un JSON que ya llega al sistema. Aquí está la mecánica completa.

1 · Cómo llegan los mensajes hoy

Cada vez que un cliente escribe por WhatsApp, Infobip hace un POST al webhook del bot con un JSON. Así funciona hoy en Quinta del Mar y así lo recibe también el prototipo de STIRPE. Un mensaje normal se ve así:

Webhook de Infobip · mensaje entrante normal
{
  "results": [{
    "from": "573001234567",          ← el celular del cliente
    "to": "573213927795",            ← el número del bot
    "messageId": "ABGGf...",
    "receivedAt": "2026-08-17T21:14:09Z",
    "message": {
      "type": "TEXT",
      "text": "Hola, quiero más información"
    }
  }]
}

El sistema lee de ahí quién escribe, a quién, y qué dijo (texto, audio, imagen, ubicación…). Con eso arma el turno de conversación. Todo lo que el bot "ve" del mundo entra por este JSON.

2 · El campo extra cuando el cliente viene de un anuncio

Cuando el anuncio es click-to-WhatsApp (botón "Enviar mensaje" en Facebook/Instagram), el cliente toca el botón, se le abre el chat y envía el primer mensaje. Ese mensaje llega por el mismo webhook — pero Meta le adjunta un objeto referral con la metadata del anuncio. El cliente no comparte ningún link: viaja por debajo, invisible para él.

El mismo webhook · cliente que llegó tocando un anuncio
{
  "results": [{
    "from": "573001234567",
    "to": "573213927795",
    "message": {
      "type": "TEXT",
      "text": "Hola, quiero más información"
    },
    "referral": {                    ← lo agrega Meta, no el cliente
      "source_type": "ad",
      "source_id": "120212345678901234", ← id del anuncio
      "headline": "Colección Denim STIRPE", ← título literal del anuncio
      "source_url": "https://fb.me/xxxx",
      "ctwa_clid": "Afg..."          ← click-id para medir conversión
    }
  }]
}

La tool atribucion_campana es, literalmente: leer ese campo y cruzar el source_id contra una tabla anuncio → campaña interna que mantiene marketing. Cero LLM, cero pregunta al cliente.

Hallazgo del repo: el normalizer del prototipo ya guarda el result completo en el campo raw de cada mensaje en Mongo. Si Infobip reenvía el referral, ya se está almacenando hoy sin que nadie lo lea — la tool consiste en leer lo que ya se guarda.
Verificación pendiente con Infobip: Meta entrega el referral; Infobip está en el medio como proveedor. Hay que confirmar en qué campo exacto de su webhook lo reenvía y si requiere habilitarse en la cuenta. Es la única incógnita de esta vía.

Cómo usar este documento

  1. En la revisión técnica: cada flujo valida las entradas y salidas de la tabla de herramientas v1 — si una conversación no se puede armar con el contrato actual, el contrato está incompleto.
  2. Como semilla del corpus de pruebas: estos 10 flujos definen el comportamiento esperado; las 20–30 conversaciones reales que se están extrayendo aportan la variedad del mundo. Con ambos, el arnés de replay tiene contra qué comparar.
  3. Como criterio de aceptación del prototipo: el prototipo "funciona" cuando F1–F4 y F6–F8 corren de punta a punta contra el backend real. F5, F9 y F10 entran al cerrar sus dependencias (identidad/habeas data, bandeja, plantilla HSM).
