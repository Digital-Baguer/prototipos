Antes de empezar

  1. Deploy de get-web: la rama feature/SOP-012 desplegada en el ambiente donde se prueba (o en local, con .env y una base get con las filas del paso 2). 
    # get-web
git fetch origin && git checkout feature/SOP-012
npm ci && npm run build
npm run test:front:sop010-detalle-documento      # 6/6
git grep -n "Consulta de Planes" -- resources/js  # vacío
  2. SQL en get (los casos 2 y 3 lo necesitan): registro-menu.sql, en la carpeta del REQ (docs/proyectos/SOP-migracion-quac-soporte/requirements/SOP-012/), base get. Sin DDL, idempotente. Sin él, el lateral sigue diciendo «Consulta de planes»: no es bug del código. La comprobación está en las pestañas 2 y 3.
  3. Usuarios de prueba (solicitarlos): uno con rol 21, 25 o 43 (ve Documentos digitales e Informe) y otro con rol 30 o 37 (solo Informe). Para el caso 3, además, uno sin el permiso acceso:quac.planes.index ni el de Documentos digitales.
  4. Dónde se entra: get-web › QUAC › Planes, dirección /quac/planes. El lateral va expandido (no contraído) salvo en el caso 5, que usa el menú móvil.
  5. Tamaños: casos 1 a 4 y regresión a 1440 px de ancho; caso 5 a 390 px (herramientas del navegador, modo móvil).
  6. Datos reales: nunca. Autorizar por override o cargar al CRM solo con un plan de prueba acordado (regresión).
