Guía visual de pruebas: el api guarda qué respondió Infobip en cada envío

Api: testapi-v2 en feature/AQ-028 (910d8) con el paquete communication-sdk v1.8.0 · get-web: feature/AQ-028 (99068), ambiente de pruebas · App: la 4.1.0 de pruebas; la app no cambia, el título y el texto de los avisos los manda el api.

Datos de ejemplo de esta guía: cédula 1000000001, celular 320 •••• 2350, correo fe•••@hotmail.com. En tu prueba usa una cédula de prueba con un celular tuyo.

Antes de empezar

  1. Paquete: tag v1.8.0 publicado. En el api: git fetch origin, git checkout feature/AQ-028 y composer update baguer/communication-sdk. Sin el paquete nuevo ningún código sale.
  2. En quacapi_dev, antes de levantar el api: correr migracion.sql (crea envios_mensajes) y crear en var_env las variables INFOBIP_WEBHOOK_URL_BASE e INFOBIP_WEBHOOK_TOKEN. El valor del token lo entrega el arquitecto; no va en la tarjeta ni en esta guía.
  3. Al usuario con que get-web lee quacapi_dev: permiso de lectura sobre envios_mensajes.
  4. get-web: git checkout feature/AQ-028, npm ci, npm run build. Menú QUAC › Diagnóstico de la app, permiso consultar_diagnostico_app, ambiente de pruebas.
  5. App 4.1.0 compilada contra testapi-v2, en un teléfono o emulador.
  6. Una cédula de prueba con un celular y un correo tuyos. No usar clientes reales: los casos 2 y 3 frenan los SMS de ese número de verdad.
  7. Una terminal con curl y una consola de MySQL sobre quacapi_dev. En la terminal: export TOKEN=… con el valor de INFOBIP_WEBHOOK_TOKEN.
