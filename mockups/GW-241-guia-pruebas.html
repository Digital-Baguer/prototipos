Portal de pagos: pedir el correo cuando el del cliente no es entregable

Un caso por cada caso mínimo de qa.md §6, con el mismo número. Cada caso muestra qué preparar, qué tocar, qué debe verse en el portal y qué debe quedar en la base. Los datos son de ejemplo: usa un cliente de prueba tuyo.

api-pagos-quac feature/GW-241 · dd3c6 pagosquac-client feature/GW-241 · 1dcde Ejemplo: CC 1000000001 · celular 300 000 0001 · Pago total $ 294.418

Antes de empezar

1. SQL antes del API (OPS-GW-241-2)

Correr api-pagos-quac/docs/sql/GW-241-migracion.sql en quacapi, una sola vez. Sin las columnas nuevas se caen todos los cobros. Esta query debe dar 10 filas:

SELECT TABLE_NAME, COLUMN_NAME
FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA='quacapi'
  AND (TABLE_NAME='client_payment_emails'
   OR (TABLE_NAME IN ('payments','pre_payments')
       AND COLUMN_NAME LIKE 'payer%'));

3. Datos que hay que pedir

  • Un cliente QUAC con crédito activo cuyo correo en el CRM no sea entregable (por ejemplo NOTIENE@gmail.com), con su celular.
  • Un cliente con correo entregable en el CRM, para la regresión.
  • Un buzón real tuyo para escribirlo en la pantalla del correo.
  • Un enlace del portal con valor y comercio, para el caso 7.

4. Dónde ver lo que pasó

-- último cobro del cliente de prueba
SELECT payment_id, channel, payment_gateway, payment_status,
       payer_email_source, payer_email
FROM quacapi.payments
WHERE client_document = '{cédula de prueba}'
ORDER BY payment_id DESC LIMIT 3;

-- correo de pago guardado
SELECT client_document, channel, updated_at
FROM quacapi.client_payment_emails
WHERE client_document = '{cédula de prueba}';

En el navegador, pestaña Red: payer-email/status y payer-email. Ninguna respuesta debe traer un correo.
